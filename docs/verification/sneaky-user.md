# 狡猾用户与状态边界验收

## 环境和范围

- EGO `taskSpace(8).page('p6')`，开发页面 `http://127.0.0.1:7001/`；`window.utools` 不存在。通过页面运行实际 Zustand store 动作，菜单项通过页面右键菜单点击；临时书签和分组在验收后恢复。
- 未连接真实 uTools：真实数据库、磁盘恢复副本、宿主退出、账号切换和跨设备同步冲突均未验证。下面内存宿主采样的适配器是模拟实现。

## 过期多分类位置：高

- 复现：书签同时位于 `eval-g/a`、`eval-g/b`；向 `updateBookmarkLocations` 传入仍存在的 `b` 和已删除的 `deleted`。
- 预期：拒绝整个操作，原索引和位置声明保持一致；提示用户重新选择。
- 修复前实际：返回后索引仅含 `b`，`bookmark.locations` 却仍包含 `deleted`，可能触发完整性检查并暂停保存。
- 修复后 p6 实测：动作返回 `false`，分组与书签的序列化内容未变化；对只含有效 `b` 的更新返回 `true`，索引和声明均为 `eval-g/b`。以不存在的分类新增返回 `null`，原数据不变。
- 证据：`src/stores/bookmark/bookmark-actions.ts` 中 `validLocations` 和 `updateBookmarkLocations`；表单保存先检查位置更新是否成功，MCP 与 AI 创建路径检查返回值。

## 只读新增伪成功：中

- 复现：将 store 设置为只读，以有效分类调用 `addBookmark`，再调用位置更新。
- 预期：不修改书签、不排队同步，新增返回失败，调用方不显示创建成功。
- 修复前 p6 实测：数据未变化，但新增返回含 ID 的书签对象。
- 修复后 p6 实测：新增返回 `null`、位置更新返回 `false`，分组和书签内容未变化。表单、MCP 与 AI 创建路径已处理失败；这些入口的完整 UI/宿主交互尚未逐一实测。

## 非法选择和失效菜单

- p6 实测：不存在的组、子组和重复选择共触发 0 次 store 更新，活动选择保持原值；追加复验软删除组和子组：选择仍为 `eval-soft/live`，store 更新通知为 0。
- p6 实测：打开多分类书签在位置 A 的右键菜单，删除 A 后点击菜单的“删除”；书签仍存在，位置 B 保留。菜单点击使用真实页面，删除分类通过页面内 store 动作触发。

## 选择持久化 O(1) 采样

- 使用真实 `createBookmarkPersistence`，10,000 条合成书签；宿主、存储、恢复和合并适配器为内存替身，Node 本地运行，非真实 uTools。
- 连续 1,000 次切换耗时 1.41 ms；计数的整库 JSON 序列化、恢复副本调用及快照写入均为 0。等待 1.1 秒后执行 flush 和模拟 pagehide，仍为 0，选择小键写入 1 次。
- 随后修改书签标题：立即观察到 1 次携带新标题的待保存恢复副本调用，flush 后快照写入 1 次；初始化可恢复有效选择 `s2`。该结果证明此适配器条件下的调用路径，不能证明真实磁盘持久化或冲突处理。

## 快照与选择保护审查

- 选择变化仅写小键；内容变化仍先生成待保存副本，写入前使用当前选择，保存和刷新路径仍保留基线比较、合并及冲突副本。以上为源码审查，真实宿主并发尚未验证。
- `utoolsStorage` 的小键使用 `gm:storage:` 文档，可能参与宿主同步，不能称为严格本机专用；小键写入也不经过书签快照的账号身份检查，账号切换期间的行为需在真实宿主确认。
- 分组 ID、子分组 ID 在选择动作校验；持久化选择恢复后还会执行 `ensureValidSelection`。非法小键回退到快照选择；真实宿主重新启动恢复尚未验证。

## 回收站恢复的过期目标：高

- 对抗源码审查发现：恢复操作先从回收站索引移除，再调用位置更新，但忽略更新失败；旧位置若已软删除，可能保留位置与索引不一致的中间状态并返回成功。只读恢复也会报告成功。此前发现基于源码推断。
- 修复后 p6 实测：书签原位置为软删除的 `eval-g/dead`，恢复返回 `true`，回退到 `eval-g/live`；两个 store 通知观察到的位置声明、回收站索引、目标索引均一致。只读恢复返回 `false`，回收站仍含书签。恢复现在在单次内容提交中更新位置声明和索引。

## 陈旧恢复与位置更新：高

- 源码复核：对未入回收站的书签调用恢复，旧实现会增加目标索引并替换 `locations`，但保留原普通分类索引，造成不一致；重复恢复同样可能发生。位置更新对已入回收站的书签仍可成功，过期编辑可把它移出回收站。
- 修复：恢复仅接受存在于回收站索引、且不同时存在于普通分类索引的书签；不依赖 `isDeleted` 标记（正常回收站数据可能未设置该标记）。位置更新拒绝已删除或已入回收站的目标。混合索引数据保守拒绝恢复，留待修复数据。
- 隔离内存 runtime Eval 调用真实 action：正常书签恢复 `false`、数据不变、同步副作用 0；回收站书签过期位置更新 `false`、数据不变；有效恢复 `true`，目标索引与声明一致；再次恢复 `false`、数据不变；混合索引恢复和 `isDeleted` 书签位置更新均返回 `false` 且数据不变，整个过程仅有效恢复产生一次内容提交。p6 页面实际使用的带版本参数 store 已复验，结果如下；真实 uTools 未连接。
- 位置更新接受的是完整目标列表，没有调用方版本或旧位置参数；如果书签仍在普通分类但另一操作已改变其位置，过期表单仍可能覆盖较新的分类选择，此问题仅源码推断，尚未建立复现或修复。
