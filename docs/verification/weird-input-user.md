## 源码审查和边界

- **混合位置已修复**。修复前真实 store 对正常合成书签调用 `updateBookmarkLocations`，同时传普通组和回收站，返回 true；此后恢复返回 false，移除普通位置也未生效。修复后在 p6 页面实际 store 复验：混合目标和纯回收站目标更新均返回 false，混合目标新增返回 null，数据不变且无同步调用；移入回收站使用专用原子动作。
- p6 页面实际 store 复验：同时位于普通分组和回收站的过期书签经自动清理后仍存在，回收站专属的过期书签被清理；另以混合书签和回收站专属书签直接清空回收站，混合书签保留在普通分组，专属书签删除，位置声明和索引一致、完整性检查通过，仅专属书签触发删除同步。页面未连接真实 uTools。
- 侧栏已移除删除确认模式及其回调；普通书签菜单关闭后不能重复消费旧删除动作。跨行双击拦截结合点击次数与位置/时间，无法保证拦截间隔超过 500ms 的两次独立点击。
- 列表筛选使用 `Set.has`，按原书签数组顺序输出；清空时建立 ID 集合和书签索引。性能复杂度判断为源码推断，没有回收站大数据计时。
- 搜索结果缺少明确位置时选取第一个索引位置；删除原子分组后恢复可能落到默认分组。以上为源码推断，未实测。
- 未编写或运行测试用例。最终源码中的性能虚拟列表等其他并行修改与验收快照存在差异；完整集成验收及 `bun run build` 由主代理统一处理。
